## 1. SalesSystemとは

SalesSystem（画面名: 営業管理システム）は、次をまとめて扱う社内システムです。

- 組織（顧客・見込顧客・メディア・自治体・学校・研究・パートナー等）
- 先方担当者
- 案件・対応履歴・次回アクション
- お問い合わせ
- 営業リスト / 営業候補 / 架電
- 契約・クレーム

**正式な関係先は組織、大量の未精査候補は営業リスト**、という二層が基本です。

---

## 2. 基本概念

詳細は [terminology.md](./terminology.md)。特に次を必ず区別してください。

- 見込顧客（組織の関係性） ≠ 営業候補（リスト上の候補）
- 対応履歴（過去） ≠ 次回アクション（未来）
- 興味なし ≠ 営業連絡不要
- 先方担当者 ≠ 自社担当者 ≠ 権限の「担当者」

---

## 3. マイデスク

ログイン後の起点です。

表示例: 今日やること / 今日の営業 / 新着お問い合わせ / 自分の案件 / 最近の対応 / 要確認 など。

おすすめ: 朝 → マイデスク → 期限超過を処理 → 今日の営業 → 問い合わせ・顧客対応。

---

## 4. 組織

正式な関係先を登録します。関係性は複数選択可。

| 関係性 | 例 |
|---|---|
| 顧客 | 契約中・継続取引 |
| 見込顧客 | 商談・提案中 |
| メディア | 取材・記事 |
| 自治体 | 市役所・実証相談 |
| 学校・研究機関 | 大学・研究室 |
| パートナー | 協業・紹介 |

**【システム仕様】** 新規で関係性未選択の場合、デフォルトで「顧客」が付くことがあります。  
**【おすすめ運用】** 商談中なら「見込顧客」、取材なら「メディア」を最初から付ける。

大量CSVは組織へ直接入れないでください。

---

## 5. 先方担当者

組織に所属する相手側の人物です。退職時は無効化（消し切りしない）。

権限名の「担当者」や案件の「自社担当者」と混同しないこと。

---

## 6. お問い合わせ

Webフォーム由来の受信箱です。通常Gmail全部は入りません。

できること: 担当割当 / 状態変更 / 既存組織候補 / 紐付け・組織作成 / 対応履歴化 / Gmail返信下書き（送信は人がGmailで）。

**【システム仕様】** お問い合わせと営業候補の自動統合はありません。

---

## 7. 営業リスト

未精査の営業候補を配布・割当・架電するための入れ物です。

- 営業候補 = 会社本体の候補
- リスト上の行 = そのリストでの担当・進捗

権限: リスト作成・CSV・一括割当は **運用責任者以上**。架電・単一担当変更は **担当者** も可。

---

## 8. CSVインポート

営業リスト詳細の「CSVをインポート」。

1. CSV選択（UTF-8 / Shift_JIS）
2. 列マッピング（会社名必須）
3. プレビュー → 実行

管理メニューの「CSV取込」は正式データ移行用で、用途が違います。

一括割当の対象は **表示中の行** です（一覧の全件ではありません）。

---

## 9. 今日の営業 / 架電キュー

自分の担当営業先へ順番に電話します。**自動発信はありません。**

流れ: 電話 → 結果選択 → 必要なら次回連絡 → **保存して次へ**。

ショートカット: 数字キー1〜7 / Ctrl(Cmd)+Enter。

「資料送付」でもメールは自動送信されません。

---

## 10. 再架電

次回連絡日時を入れると、期限超過・本日再架電としてキューに出ます。  
未来の予定は、既定対象には出ません（時間到来後）。

折返し希望は次回日時が必須です。

---

## 11. 営業連絡不要

「もう営業電話しないで」→ **営業連絡不要**（DNC）。

興味なし（今回の対象外）とは強さが違います。DNCは別リストでも再架電対象外です。

---

## 12. 正式組織への昇格

興味あり・アポ獲得でも **自動では組織になりません**。手動で昇格します。

流れの例:

```
営業リストの株式会社ABC
  → 架電 → アポ獲得
  → 正式組織へ昇格（見込顧客）
  → 先方担当者
  → 対応履歴 / 次回アクション
  → 必要なら案件
```

既存組織候補があるときは紐付けを優先。社名だけの一致は自動同一判定しません。

---

## 13. 対応履歴

過去の記録。削除機能はありません。

「次回アクション(入力記録)」は履歴用メモで、正本ToDoではありません。

---

## 14. 次回アクション

未来のToDo。マイデスクの「今日やること」に出ます。終わったら「完了」。

---

## 15. 案件

具体商談の管理。

**【おすすめ】** 問い合わせだけ・興味ありだけでは作らない。導入条件などが具体化してから。  
**【システム仕様】** 昇格時の案件作成は既定OFF。

---

## 16. 契約

契約名・期間・金額・支払状況・自動更新・契約書URL・請求条件などを管理します。

**請求書の作成・発行・管理は freee で行います。**  
SalesSystemに請求書作成機能はありません。

---

## 17. クレーム

重要度・期限管理が必要な重大トラブル用。軽い確認は対応履歴で十分なことが多いです。

---

## 18. 検索

ヘッダ検索で組織・営業候補・担当者・案件などを横断検索。  
結果はグループ分けされ、営業候補にはバッジ（営業候補 / DNC / 正式組織化済み）が表示されます。

---

## 19. ユーザー権限

| 表示名 | イメージ |
|---|---|
| 管理者 | 設定・ユーザー・同期・取込設定など |
| 運用責任者 | 日常業務 + 営業リスト運用・CSV・一括割当 |
| 担当者 | 日常の顧客対応・問い合わせ・架電・記録 |
| 閲覧者 | 閲覧のみ |

上下関係というより役割の違いです。

### 管理者向け: ユーザー管理

`管理 → ユーザー管理` で次の操作ができます。

- **直接追加**: 「ユーザーを追加」から表示名・メール・初期パスワード・権限を入力します。招待メールは送信されず、作成直後から入力したメールとパスワードでログインできます。
- **メール招待**: 本人に登録してもらう従来方式は「メールで招待」から利用できます。
- **パスワード再設定**: ユーザー行の操作メニューから新しいパスワードを設定します。パスワードは保存・再表示されません。
- **利用停止 / 再有効化**: 退職・休止時は物理削除せず利用停止にします。過去履歴は残り、新しい担当候補から除外されます。

利用停止前に表示される担当中データ件数を確認し、必要なら先に担当を変更してください。自分自身の停止・管理者権限解除、および有効な管理者が0人になる操作はできません。

## 20. よくある業務例

カテゴリ別の詳細Q&Aは [faq.md](./faq.md)（50問超）を参照。

### 問い合わせ
- Web問い合わせが来た → 担当決定 → 既存確認 → 紐付け/作成 → 返信 → 履歴
- メディア取材 → 組織（メディア）→ 対応履歴
- 自治体実証 → 組織（自治体）→ 必要なら案件

### 営業
- 500社CSV → 営業リスト → 割当 → 架電
- 担当者不在 → 次回連絡 → 再架電
- アポ → 正式組織へ昇格

### 顧客対応
- 検索 → 組織 → 対応履歴 → 次回アクション
- 具体商談 → 案件

### 契約・トラブル
- 契約情報は契約へ / 請求は freee
- 重大不具合はクレーム

## 21. よくある間違い

1. 営業CSVを全部組織へ入れる → 営業リストへ
2. 電話内容を次回アクションだけに書く → 過去は対応履歴（または架電結果）
3. 既存顧客なのに新規組織を作る → 検索・紐付け
4. 興味なしと営業連絡不要を同じにする → 強さが違う
5. 営業候補と正式組織を二重育成する → 昇格して寄せる
6. 資料送付でメール自動送信を期待する → 送信なし
7. アポで自動組織化を待つ → 手動昇格
8. お問い合わせ＝全Gmailと思う → 対象限定
9. 入力記録を正本ToDoと思う → 次回アクションを別途作成
10. 一括割当が全件に走ったと思う → 表示中の行のみ
11. 未来の再架電が出ないと壊れたと思う → 既定では出ない
12. 請求書をSalesSystemで作ろうとする → freee
13. 閲覧者に振分けを頼む → 編集不可
14. 電話結果を保存しない → 必ず保存して次へ
15. 関係性未設定のまま顧客デフォルトに気づかない → 関係性を明示

---

## 22. 現在対象外の機能

SalesSystem単体では行いません。

- 自動発信
- 自動メール送信 / 一斉メール
- 問い合わせと営業候補の自動統合
- 名刺読み取り
- 大規模BI
- **請求書発行（freee）**
