# UI・デザインガイドライン

本システムはPC利用を最優先とする業務ツールである。参考にする操作パターン: Salesforceの情報密度、HubSpotの導線、Linearの操作速度、kintoneの項目柔軟性、Notionの編集しやすさ(他社ブランド資産の複製は禁止)。

## 1. デザイントークン

### カラー

ブランドカラー(オレンジ)には寄せず、落ち着いた独立カラーを採用する。

| 用途 | 方針 |
|---|---|
| ベース | 白〜ごく薄いグレー(`slate-50`系)。ダークモードは初期版対象外 |
| テキスト | 濃いスレート(`slate-900` / 副次 `slate-600`) |
| プライマリ(アクション) | 落ち着いた青系スレート(`slate-700`〜`blue-700`程度の彩度低め)。1色に統一 |
| 罫線・区切り | `slate-200`系。情報の区分は罫線と背景色の濃淡で行う |
| セマンティック | 成功=緑 / 警告=琥珀 / エラー・期限超過=赤 / 同期警告=琥珀。意味のある場所にのみ使用 |
| マスタの色 | Notion標準色名(gray/blue/green/…)を彩度を抑えたバッジ配色にマッピング |

禁止: 紫・青のグラデーション、ガラス風・半透明UI、装飾目的の色使い。

### タイポグラフィ・密度

- フォント: システムフォントスタック(Noto Sans JP系フォールバック)。
- 基本サイズ 13〜14px、テーブルは13px。ページ見出しは18px程度まで(大きすぎる見出し禁止)。
- 行の高さ: テーブル行 32〜36px、フォーム行 40px程度。業務ツールとして自然な密度を保つ。
- 角丸は小さく(4〜6px)。カードの多用より罫線・背景で区分する。
- 余白は8pxグリッド。無駄に広い余白を作らない。

## 2. UI原則

- 保存状態・通信中・エラーを常に明示する(送信中はボタンをスピナー付き無効化=二重クリック防止)。
- 破壊的・不可逆操作(アーカイブ、一括登録の確定、CSV本登録)には確認ステップを入れる。逆に単純保存に確認モーダルは出さない。
- 成功通知は控えめなトースト1つ。過剰に出さない。
- 入力中の内容を失いにくくする: 未保存で画面遷移するとき警告。フォーム値はエラー時も保持。
- 編集はできる限りその場(インライン・サイドパネル)で行い、モーダルの多段化・全面モーダル編集を避ける。
- アイコンには必ずテキストラベルまたはツールチップを併記(アイコンのみで意味を判断させない)。
- 重要度の違う情報は見た目で差を付ける(期限超過は赤、警告バナー、主要KPIは大きめ数値)。
- 日本語UIとして自然な文言(「〜が完了しました」「〜できませんでした。再試行してください」)。エラーは原因と次の行動を示す。
- テーブルの横スクロールを最小限に: 既定の表示列を厳選し、列表示切替で拡張。左端の主要列(表示名)は固定列。
- 詳細画面への移動回数を減らす: 一覧の行から簡易プレビュー、プレビューから履歴追加等の主要操作へ直接進める。
- キーボード操作: `/` で検索フォーカス、`Esc` でパネルクローズ、テーブルの上下移動+Enterで詳細、フォームのTab順序を論理的に。フォーカスリングを消さない。
- レスポンシブ: PCレイアウト優先。スマートフォンでは閲覧+最低限の履歴登録ができる程度の縮退表示(テーブルは主要列のみ)。

## 3. 避けるデザイン(禁止パターン)

- 無意味に大きな角丸カード / すべての情報のカード化
- 紫・青グラデーション、ガラス風・半透明UI
- 無駄に広い余白、情報量が極端に少ないダッシュボード
- 装飾目的だけのグラフ、大きすぎる見出し、過剰なアニメーション
- 操作のたびのモーダル表示
- アイコンだけで意味を判断させる
- 重要度が違う情報をすべて同じ見た目にする
- モバイルアプリ風の巨大ボタンをPC画面に並べる
- コンポーネントライブラリのデモ画面のようなUI(shadcn/uiはプリミティブとして密度・余白・罫線を調整して使う)

- ヘッダーのグローバル検索は組織のインクリメンタル検索(表記揺れ吸収・関係性バッジ)で、結果から直接詳細へ。

## 5. 画面別ワイヤーフレーム

### 5.1 ログイン

中央寄せの小さなフォーム1枚(カード装飾は最小限)。メール+パスワード、Googleでログインボタン、パスワード再設定リンク。エラーは具体的文言([permissions.md §4](./permissions.md#4-認証設計))。

### 5.2 マイデスク

```
| 今日の対応予定 (N件)     | 期限超過 (N件・赤)      | 直近の次回アクション   |
|  リスト(顧客名/内容/時刻)|  リスト               |  リスト               |
+--------------------------+------------------------+------------------------+
| 今月KPI: 対応件数  商談件数  受注件数  受注金額   ← クリックで条件付き一覧へ |
+---------------------------------------------------------------------------+
| 営業ステータス別件数(横バー・数値)  | 事業区分別の案件状況(数値表)        |
+---------------------------------------------------------------------------+
| 担当顧客 | 担当案件 | 最近閲覧した顧客 | 最近更新された顧客 (タブ切替リスト) |
```

- 上段3リスト(本日対応予定・期限超過・直近の次回アクション)は**次回アクションのインデックス(action_index)を正式な参照元**とし、自分が担当のものを表示する([supabase-schema.md](./supabase-schema.md#10-集計マイデスクkpi))。行クリックで顧客詳細へ。アクションの完了はリスト上から直接操作できる。
- KPI・集計値はすべてクリック可能で、該当条件が設定された顧客/案件一覧へ遷移する。受注件数・金額は案件ステータスのsemantic_key=`won`、商談件数は対応履歴分類の**semantic_tagsに `meeting` を含む**分類で集計する。
- 装飾グラフは置かない。集計は数値と最小限のバー表示のみ。
- 「+新規顧客」ボタンと検索への導線をヘッダーに常設。

### 5.3 組織検索・一覧（旧: 顧客）

```
| 検索ボックス(大・上部固定) [保存済み検索▼] [列設定] [エクスポート]       |
| フィルタ: [タグ AND/OR] [事業区分] [ステータス] [担当] [都道府県] [期間…] |
+---------------------------------------------------------------------------+
| □ | 表示名(固定列) | 会社名 | 住所 | 電話 | 担当 | ステータス | 最終対応 |…|
| □ | 株式会社A 介護…| …    |      |      |      | 商談中     | 8/1      |  |
+---------------------------------------------------------------------------+
| N件選択中: [対応履歴を一括登録] [一括更新▼(権限がある場合)]                |
| ページネーション                                    | プレビューパネル → |
```

- 列は「基礎情報」(会社名・施設名/事業所名/部署名・都道府県/住所・顧客担当者・電話・メール・事業区分・タグ)と「営業情報」(ステータス・自社担当者・最新対応内容・最終対応日・次回アクション・次回予定日・見込み金額・優先度・集客ルート)にグループ化。列設定でグループごと/列ごとに表示切替・列幅調整・固定。
- 並び替えは列ヘッダークリック。既定は最終対応日降順。
- 検索条件・フィルタ・ソート・ページはURLクエリに保存(共有・ブックマーク・戻る対応)。
- 保存済み検索: 現在の条件を名前を付けて保存、サイドナビにピン留め可能。
- 行クリックで右側に簡易プレビューパネル(主要項目+直近履歴3件+「詳細を開く」「履歴追加」)。ダブルクリック/Enterで詳細へ。
- 複数選択→「対応履歴を一括登録」: 選択件数と対象一覧を確認する画面(パネル)を挟んでから登録([csv-import-design.md] とは別の、履歴一括登録フロー)。

### 5.4 組織詳細（旧: 顧客詳細）

- 関係性は multi badge（顧客/見込顧客/メディア等）。一覧タブと FilterDisclosure で絞り込み。

```
| 株式会社A 介護事業部   [商談中] [介護福祉] [タグ] 同期警告バナー(必要時) |
| 担当: 山田 | 次回: 見積送付 (8/10・超過なら赤) | [編集] [履歴追加] [案件追加] |
+------------------------------+--------------------------------------------+
| 基礎情報                     | 営業情報                                    |
|  会社名 / 事業所名           |  ステータス / 自社担当者 / 集客ルート / 優先度 |
|  住所(〒・都道府県・以降)    |  最新対応内容 / 最終対応日                   |
|  電話 / メール / Web / 代表者 |  次回アクション / 次回予定日 / 見込み金額     |
|  顧客担当者(役職・連絡先)    |  案件一覧(名称/ステージ/金額/次回予定)       |
|  関連アカウント(リンク)      |                                            |
+------------------------------+--------------------------------------------+
| タブ: [対応履歴] [全活動]   [絞り込み: 分類▼ 期間] [+履歴追加]            |
|  ▸ 8/01 [電話][資料送付] 見積の件で担当者と通話  山田  次回: 8/10        |
|  ▾ 7/28 [訪問] 初回訪問ヒアリング  佐藤  次回: 8/01                      |
|     本文(展開時のみ表示・Notionページ本文から取得) / 編集 / 編集履歴     |
+---------------------------------------------------------------------------+
| 次回アクション (未完了)  [+アクション追加]                                |
|  リスト: 期限 / 内容 / 担当 / 優先度 / [完了]ボタン(期限超過は赤)         |
+---------------------------------------------------------------------------+
| 契約 (専用セクション)  [+契約追加]                                        |
|  テーブル: 契約名 / 区分 / 金額 / 期間 / 支払状況 / 状態                   |
+---------------------------------------------------------------------------+
| クレーム (専用セクション)  [+クレーム追加]                                |
|  テーブル: 発生日 / タイトル / 重要度 / 責任者 / 期限 / 状況               |
```

- 履歴は時系列(降順)。通常時は1行(日時・分類バッジ・タイトル・登録者・次回予定日)のみ。クリックで展開し本文(Notionページ本文ブロック)を遅延取得。全件常時展開はしない。
- **「全活動」タブ**: 対応履歴に加えて、案件の受注・失注、契約の作成・解約、クレームの発生・解決、次回アクションの完了などのイベントを**表示上のみ時系列に統合**したタイムライン。データはactivity_index / deal_index / contract_index / complaint_index / action_indexから合成し、**正式データは従来どおり各Notion DBに分離して保持する**(統合用の新しい正本は作らない)。行クリックで各エンティティの該当セクション・詳細へ。
- 履歴の編集はインライン展開内で行い、「編集履歴」リンクから監査ログ(該当ページ絞り込み)へ。
- 履歴の登録・編集フォームには「次回アクション」欄があり、入力すると次回アクションDBに正本レコードが作成される([notion-schema.md §7](./notion-schema.md#7-次回アクション-db新規9つ目))。
- ヘッダーと営業枠の「次回アクション/次回予定日」は未完了アクションの最短期限から自動導出された値であり、直接編集ではなくアクションの操作(完了・期限変更)で変わることをUI上も示す。
- 関連アカウントは自分が指す先+自分を指す元の双方向を統合表示。クリックで該当詳細へ。
- 編集は項目グループ単位のサイドパネルまたはインライン編集(全面モーダル禁止)。編集開始時に最新の正本を再取得し、競合時は通知([sync-design.md §1](./sync-design.md))。

### 5.5 ユーザープロフィール

営業ツール上の利用者プロフィール(人事情報ではない)。氏名・メール・権限・所属/役割、担当顧客リスト・担当案件リスト、今月KPI(対応・商談・受注件数・受注金額)、期限切れアクション、最近の活動(自分の監査ログ要約)。KPI・リストはクリックで条件付き一覧へ。

### 5.6 管理画面

サイドナビ第2階層: ユーザー管理 / マスタ管理 / CSVインポート / CSVエクスポート / 監査ログ / 同期状況 / 同期エラー / Notion削除確認 / システム設定。

- ユーザー管理: 一覧(氏名・メール・権限・状態・プロビジョニング状態・最終ログイン)+招待フォーム(有効期限付き)+権限変更+無効化。
- マスタ管理: 種別タブ(事業区分/タグ/ステータス/…)→ 名称・色・表示順(ドラッグ並び替え)・有効/無効・semantic_key(管理者のみ表示)。無効化時は「既存データの参照は維持されます」を明示。**新しいマスタ種別そのものの追加は開発対応が必要**である旨を画面に明記する。
- 監査ログ: 期間・実行者・操作種別・対象で絞り込み。行展開で変更項目のbefore/after差分表示(本文はハッシュ・要約・文字数)。Notion側変更は「変更前は記録されません」の注記。
- CSVエクスポート: 「高速(一覧項目のみ・即時)」と「完全(全項目・Notionから取得・時間がかかる)」の2方式を明示的に選択([csv-import-design.md §5](./csv-import-design.md#5-エクスポート設計))。
- 同期状況/同期エラー/Notion削除確認: [sync-design.md §8](./sync-design.md#8-同期状態の可視化) の構成。同期状況にはジョブ滞留(スケジューラー死活)と**Notionスキーマ変更の警告**を含む。
- システム設定: Notionスキーマスナップショットの確認、データソース書込の一時停止、Notion接続状態の確認。

## 6. コンポーネント実装方針

- shadcn/ui(Radixベース)を導入し、`components/ui/` でトークン(上記カラー・密度)を反映した本システム版として調整する。デモそのままの見た目で画面に並べない。
- 高頻度コンポーネント: 高密度テーブル(TanStack Table統合)、マスタバッジ(色付き)、日付表示(JST、相対+絶対)、ステータス変更ドロップダウン、検索コンボボックス(表記揺れ対応)、サイドパネル(Sheet)、確認ダイアログ、トースト、同期状態インジケーター。
- 空データ状態: 各一覧・セクションに「まだ登録がありません+最初の登録アクション」を用意する。ローディングはスケルトン(過剰アニメーション禁止)。
